# Phase 1.5 — Execution Domain Model

Version: 1.0

Status: Architecture Freeze

---

# Goal

Define the universal execution model used throughout TraceForge.

This phase contains NO implementation.

It defines the language, entities, relationships, and rules that every future
SDK, plugin, recorder, storage engine, exporter, dashboard, and AI integration
must follow.

After approval, this document becomes frozen.

---

# Vision

TraceForge is not a logger.

TraceForge is not a profiler.

TraceForge is not an observability platform.

TraceForge is an Execution Recording Platform.

Its purpose is to reconstruct the complete execution story of an application.

---

# Core Philosophy

Everything that happens inside an application is represented as an execution graph.

Different technologies produce different execution nodes.

The recorder never cares where a node came from.

It only records facts.

No analysis.

No interpretation.

No AI.

Only truth.

---

# The Runtime Hierarchy

Recording Session

↓

Activities

↓

Execution Graph

↓

Execution Nodes

---

# Recording Session

A recording session represents one developer recording.

Example

Developer presses:

Start Recording

Developer tests the application.

Developer presses:

Stop Recording

Everything that happened belongs to one Recording Session.

A session contains:

- Session ID
- Started At
- Finished At
- Duration
- Environment
- Activities

---

# Activity

An Activity is one meaningful user action.

Examples

User Login

Checkout

Search

Upload Image

Create Invoice

Each activity owns one execution graph.

Activities should remain human-readable.

---

# Execution Graph

Each activity contains exactly one execution graph.

The graph represents everything that happened while that activity executed.

The graph is always a Directed Acyclic Graph (DAG).

Cycles are not allowed.

---

# Execution Node

Execution Nodes are the atomic units of execution.

Everything becomes a node.

Examples

Function Call

HTTP Request

HTTP Response

Database Query

Redis Operation

Cache Lookup

LLM Call

Filesystem Read

Filesystem Write

Message Queue Publish

Message Queue Consume

Exception

Conditional Branch

Loop

Custom Business Step

Framework Lifecycle Hook

Render

Widget Build

Background Task

Thread Spawn

Anything else

No technology-specific assumptions exist inside the recorder.

# Relationships

Nodes may have:

Parent

Children

Dependencies

Previous

Next

Cycles are forbidden.

---

# Source

Each node records where it originated.

Examples

Python SDK

Node SDK

FastAPI Plugin

React Plugin

Flutter Plugin

SQL Plugin

Redis Plugin

Filesystem Plugin

Manual Instrumentation

Unknown

---

# Inputs / Outputs

Every node may contain:

Inputs

Outputs

These should be serializable whenever possible.

Large payloads may be truncated by recording profiles.

---

# Metadata

Metadata contains additional information that does not belong in inputs or outputs.

Examples

SQL duration

HTTP headers

Database name

HTTP status

Model name

Cache hit

GPU

Thread ID

Anything useful for debugging

---

# Recording Profiles

The recorder supports configurable capture policies.

Examples

Minimal

Standard

Forensic

Profiles determine:

- Which node types are captured
- Payload limits
- Variable capture
- Stack capture
- Sampling
- Privacy rules

Profiles never change the graph model.

---

# Plugins

Plugins never modify the execution graph directly.

Plugins only emit execution nodes.

The recorder builds the graph.

---

# Recorder

The recorder owns:

- Session lifecycle
- Activity lifecycle
- Graph construction
- Relationship validation
- Timestamp ordering
- Node indexing

The recorder performs no debugging.

---

# AI

AI is never involved while recording.

Recording must be deterministic.

AI consumes exported traces after recording has finished.

---

# Storage

Storage is an implementation detail.

The execution model is storage-independent.

Possible future storage:

Memory

SQLite

JSONL

Parquet

Cloud

The model never changes.

---

# Export

Exporters transform the execution model into formats.

Examples

trace.json

trace.jsonl

OpenTelemetry

Mermaid

GraphML

SQLite

ZIP bundle

Exporters never modify execution data.

---

# Dashboard

The dashboard is a visualization layer.

Possible views

Timeline

Tree

Graph

Dependency Graph

Sequence Diagram

Statistics

Heatmap

All views are generated from the same execution graph.

---

# Non Goals

The execution model must never:

Contain AI-generated analysis

Contain recommendations

Contain inferred bugs

Contain automatic fixes

Guess missing information

Modify execution history

It records only observable facts.
